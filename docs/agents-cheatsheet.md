# Памятка: работа с Claude Code и агентами

Заметки по ходу обучения. Дополняем по мере практики; примеры взяты из этого проекта.

## 1. Базовые принципы

- **Проси результат и критерий готовности**, а не последовательность команд.
  Пример: «починить парсер так, чтобы можно было отличить наше исключение, тесты менять свободно».
- **Сначала варианты, потом код.** Фраза «код пока не меняй, предложи варианты с плюсами и минусами»
  дешёвый способ выбрать подход до того, как что-то написано.
- **Сообщай ограничения сразу**: «внешних клиентов нет, обратная совместимость не нужна»
  это изменило решение (можно ломать API).
- **Явно говори, чего НЕ делать** («tryParse не добавляй»), иначе агент может расширить задачу.
- **Правки видны и откатываемы.** Если не нравится способ (скрипт с регулярками),
  скажи об этом, и агент перейдёт на обычные правки по одной.
- **Проверяй, а не верь.** Просить прогнать тесты и показать результат нормально.

## 2. Безопасность и git

- Агент коммитит и пушит только по просьбе. Просматривай `git status` перед `git add -A`:
  в нашем случае туда попали `target/` и `.idea/`, поэтому нужен `.gitignore`.
- Пуш наружу, удаление и перезапись подтверждай осознанно.
- Токены и пароли агент не вводит: вход в GitHub делаешь ты (Git Credential Manager или токен).
- Посторонние правки файлов (например, автоподстановка IDE) агент не откатывает сам, а сообщает.

## 3. Когда нужен подагент, а когда нет

| Ситуация | Что делать |
|---|---|
| Найти пару мест в коде, прочитать один файл | Сам агент, подагент не нужен |
| Широкий поиск по многим файлам, нужен только вывод | Подагент `Explore` |
| Спроектировать реализацию крупной фичи | Подагент `Plan` |
| Независимые куски работы, которые можно вести параллельно | Несколько подагентов в одном запросе |
| Непредвзятое ревью | Свежий подагент, которому дают код, а не готовые выводы |
| Отдельная долгая задача со своей веткой/PR | Отдельная сессия |

Правило: подагент знает только то, что ты написал в его задании, а в ответ ты получаешь краткий отчёт.
Поэтому задание нужно формулировать как коллеге: цель, что уже исключено, где смотреть.
Лишние агенты стоят токенов, и в сомнении лучше не запускать.

## 4. Файл CLAUDE.md

Файл в корне проекта, который агент читает в начале каждой сессии: как собирать, как запускать тесты,
соглашения по коду, чего не трогать. Создаётся командой `/init`, потом правится руками.
Пиши туда то, что нельзя вывести из кода.

## 5. Скиллы (skills)

**Что это.** Заготовленная инструкция для типовой задачи: ревью, деплой, оформление документов.
Когда задача подходит под описание скилла, его инструкции подгружаются в работу.

**Как вызывать.** Командой `/<имя-скилла>`, например `/code-review`, `/simplify`, `/init`,
либо агент берёт скилл сам, если описание подходит под задачу.

**Из чего состоит.** Папка со скиллом, в ней файл `SKILL.md` с шапкой (`name`, `description`) и текстом инструкции,
плюс при необходимости скрипты и справочные файлы. Хранится в проекте (`.claude/skills/`, общий для команды)
или у пользователя (`~/.claude/skills/`, для всех проектов).

**Главное в скилле — `description`.** По нему агент решает, когда скилл применять.
Пиши, что скилл делает и в каких случаях срабатывает.

**Как создать.** Проще всего попросить агента вызвать скилл `skill-creator`.
Подходит, когда одну и ту же инструкцию приходится повторять больше двух-трёх раз.
Детали формата сверяй с актуальной документацией, они меняются.

## 6. Подагенты собственного типа

Файл в `.claude/agents/<имя>.md` с шапкой (имя, описание, набор инструментов, модель) и системным промптом.
Нужен для постоянной роли, например «ревьюер, который только читает и ничего не правит».
Ограничивая инструменты, ограничиваешь и возможности агента.

## 7. Права, хуки, память

- **Права (permissions).** В `settings.json` задаётся, что разрешено без вопроса (например, `mvn test`).
  Скилл `fewer-permission-prompts` по истории работы предлагает список безопасных разрешений.
- **Хуки (hooks).** Автоматические действия по событиям: «после каждой правки запускай форматтер».
  Если нужно «всегда делай X», а не «в этот раз», это хук, а не просьба в чате:
  память и просьбы агент может забыть, хук срабатывает всегда. Настраивается через скилл `update-config`.
- **Память.** Агент может сохранять предпочтения между чатами (например, «правки только обычным редактированием»).
  Просить прямо: «запомни, что ...».

## 8. Рабочий цикл

1. Описать задачу, ограничения и критерий готовности.
2. Для неочевидного: попросить варианты без кода.
3. Выбрать вариант, агент правит маленькими шагами.
4. Тесты проходят: просим показать результат, а не слова «готово».
5. Смотрим `git status`/`git diff`, потом коммит.
6. Пуш наружу только осознанно.
